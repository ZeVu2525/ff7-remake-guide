# FINAL FANTASY VII REMAKE 攻略ガイド（骨組み）

非公式のチェックリストです。Chapter 1 から Chapter 18 までの枠と、依頼・トロフィー・召喚獣・敵の技・マテリア・武器の台帳だけが入っています。攻略の中身は、まだ仮のカードです。

ゲーム本編の文章、画像、商標は権利者のものです。このリポジトリが配るのは、進行を記録するための画面とデータ枠です。

## 流用元

画面の殻は、公開リポジトリ [ZeVu2525/xenoblade-chronicles-de-100-guide](https://github.com/ZeVu2525/xenoblade-chronicles-de-100-guide) の `main` から構造だけを流用しています。タブで画面を切り替えること、章ごとのカードとチェック、期限と取り逃しの帯、検索、進行の保存と JSON の書き出し・読み込み、テーマ、編集モード、サービスワーカーによるオフライン対応がそれにあたります。

ゼノブレイドの攻略文、画像、第三者データは含めていません。コードのライセンスは [LICENSE-CODE.md](LICENSE-CODE.md)（MIT、Copyright (c) 2026 finalpantasy）です。

## 構成

| ファイル | 役割 |
| --- | --- |
| `index.html` | 画面。上部のタブ、帯、検索、テーマ、使い方 |
| `app.js` | チェック、絞り込み、保存、書き出しと読み込み |
| `data/game.js` | タイトル、章一覧、フラグ、画面一覧、保存キー、キャッシュ名 |
| `data/route.js` | 本編・HARD・INTERmission の章とカード |
| `data/catalogs.js` | 依頼、トロフィー、召喚獣、敵の技、マテリア、武器 |
| `progress.js` | 進行 JSON の形 |
| `edit-mode.js` | 表示文の修正。`?edit=1`、ページ下のトグル、「編集モードを終了」 |
| `sw.js` | オフライン用キャッシュ |
| `validate-guide.js` | ID の重複と必須項目の検査 |
| `test-guide.js` | ブラウザを使わない動作テスト |

別のゲームに作り替えるときは、まず `data/game.js` のタイトル、章、フラグ、画面、保存キーを変えます。カードの中身は `data/route.js` と `data/catalogs.js` です。画面の動きは共通のままにしてあります。

## データの追加

### 章のカード

`data/route.js` の、足したい章の `items` にオブジェクトを追加します。ID は `ch01-03` のように、章の中で一度決めたら変えません。

```js
{
  id: "ch03-02",
  flag: "missable",       // story / deadline / missable / request / optional / trophy / item / tips
  title: "カードの見出し",
  detail: "自分の言葉で書いた手順。",
  deadline: "次の章に入る前",  // 期限・取り逃しのとき
  trophy: "trophy-ch03",      // flag が trophy のとき。台帳の id
  source: "https://example.com/page"
}
```

フラグは `data/game.js` の `flags` と揃える。本編は進行、期限と取り逃しは帯に出る。依頼、任意、トロフィー、アイテム入手、Tips は絞り込みのチップになる。

トロフィーのカードは `trophy` に台帳の id を書く。そのカードをオンにすると、トロフィー画面の同じ項目もオンになる。カードを外したとき、同じトロフィーを指す別のカードがまだオンなら、台帳はオンのまま残る。台帳を直接オンにしても進行カードは動かない。台帳を直接オフにすると、結んである進行カードも外れる。運命の覇者は、ほかのトロフィーがすべてオンのときだけオンになる。書き出した JSON には、カードとトロフィーの両方が入る。

仮のまま残すカードは `example: true` にし、見出しに「例」と書きます。本番のカードでは両方を外します。

HARD と INTERmission は `hard` と `intermission` に、本編とは別のカードとして置きます。チェックも別々に保存されます。章の表示名は `data/game.js` の `chapters` です。公式の章題は書かず、`Chapter 1` のような番号にしてあります。

### 台帳

`data/catalogs.js` の配列に足します。今は形を示す仮データが 1 件ずつ入っています。

```js
{
  id: "quest-01",
  name: "依頼名",
  area: "受注できる場所",
  detail: "条件と報酬を自分の言葉で書く。",
  source: "https://example.com/page",
  missable: false
}
```

ID はルートのカードと重ならないようにします。

### 文章の方針

攻略サイトの文章や表を、そのまま貼らないでください。確認した事実を自分の言葉で書き、出典の URL を `source` に残します。`source` が空でもカードは表示されます。URL を書くときは `https://` から始めます。

## 保存キー

同じ GitHub Pages のドメインでも、別のガイドと進行が混ざらないように、キーを分けています。

| 用途 | キー |
| --- | --- |
| チェックの進行 | `ff7r-guide-state-v1` |
| 編集モードの文面 | `ff7r-text-edits-v1` |
| カード編集の差分 | `ff7r-card-edits-v1` |
| 表示中の章 | `ff7r-guide-chapter-filter` |
| オフラインキャッシュ | `ff7r-guide-v15` |

テーマと、リセット前の控えは、同じ `ff7r-` の別キーです。定義は `data/game.js` の `storage` と `cache` にまとめてあります。

## 編集モード

- ページ下の「編集モード：オフ」を押すと、その場でオンになる
- `?edit=1` でも入れる
- オンのあいだ、上部に「編集モードを終了」が出る
- 表示中の文をクリックすると、その文だけを直せる。進行チェックは変わらない

## 編集

ページ下の「編集」一つで、カードの追加や並べ替えと、表示文のクリック修正の両方がオンになる。`?cards=1` でも `?edit=1` でも入れる。クリックで直せるのはカードの見出しと、子チャプターの名前とメモだけです。本文をクリックするとカードの編集が開き、改行、太字、画像、2列を足せます。ボタン名は「設定」タブで変えます。バーの「ⓘ」に、書き出しと読み込みの説明があります。「書き出す」で、ルート、台帳、編集データの控え、地図、カードの画像、定型文、設定、表示文の修正から選べます。

子チャプターは章とカードの間にある。カードの番号は、その章の中で子チャプターをまたいで 1、2、3 と続く。子チャプター自身の (1) (2) は、その章の並び順で自動に付く。名前の欄には名前だけが入る。子チャプターの地図は、その中のカードが自分の地図を持たないときに使われる。見出しの定型文は「設定」タブで足したり並べ替えたりでき、同じ章の中で 宝箱①、宝箱② のように番号が付く。

## カード編集

ページ下の「カード編集：オフ」、または `?cards=1` で入る。原稿の `data/route.js` と `data/catalogs.js` はそのままで、追加・修正・削除・順番の差分だけをブラウザに残す。IDは作ったときに決まり、直しても動かしても変わらない。削除すると、そのカードのチェックは外れ、トロフィーの紐付けも残りのカードから計算し直す。

- 各章の「カードを追加」で見出し、本文、タグ、期限、トロフィーの紐付け、地図を入れる。出典のURLはデータに残し、画面には出さない
- 編集中に枠の外やEscを押しても閉じない。閉じるのは「保存」か「キャンセル」「×」で、保存していない変更があるときは確認する
- 本文は空でも保存できる
- 各カードの「＋追加」は、そのカードの直後に新しいカードを足す。子カードのときは、同じ親の子として足す。章の見出しの「カードを追加」も使える
- つまみをドラッグし、カードの右へ寄せるか右へずらして落とすと、そのカードの子になる。左へずらすか、親同士のあいだへ落とすと子から外れる。子を持つカードや、すでに子であるカードの中へは入れられない。落とした位置は青い線、子にする位置は右にずらした線で示す
- カード左の「⋮⋮」をドラッグして動かす。青い線が落ちる位置で、閉じた章や空の章の見出しへ落とすとその章の末尾に入る。電話ではそのつまみを押さえたまま動かす
- 「上へ」「下へ」「移動」でも同じ差分に残る。別の本編 / HARD / INTERmission へは「移動」か、その章の見出しへドロップ
- 台帳の画面でも、同じ操作で項目を足せる
- 「ルートJSを書き出す」は、差分を重ねた `data/route.js`。「台帳JSを書き出す」は `data/catalogs.js`。リポジトリへ戻すときは、そのファイルを置き換える
- 「編集データを書き出す」は差分だけの JSON。進行の「進行を書き出す」にも同じ差分が入る
- 「編集をすべて戻す」で差分を消す。チェックした進行は残る

原稿にカードが増えても、並べ替え済みの章では、その新しいカードが元の位置付近に差し込まれる。削除したカードは、原稿に残っていても表示しない。

## ローカルで開く

サービスワーカーを使うときは、ファイルを直接開かず、ローカルサーバで開きます。

```bash
python -m http.server 8765
```

ブラウザで `http://127.0.0.1:8765/` を開きます。

検査は依存パッケージなしで動きます。

```bash
node validate-guide.js
node test-guide.js
```

## GitHub Pages

このリポジトリは、`main` ブランチのルートをそのまま公開できます。

1. GitHub のリポジトリで Settings → Pages を開く
2. Build and deployment の Branch を `main`、Folder を `/ (root)` にする
3. 保存する

公開 URL は `https://<ユーザー名>.github.io/ff7-remake-guide/` です。`.nojekyll` を置いてあるので、Jekyll はファイルを加工しません。

`main` へマージしたあと、見ている人の操作は要りません。次にページを開くか、タブに戻ったときに新しいファイルを取り、画面を読み直します。オフラインのときだけ、直前に開いた版を出します。キャッシュを手で消す必要はありません。

この版より前のサービスワーカーが残っている端末は、ページを再読み込みしてください。1回目がまだ古い骨格のままなら、もう一度読み込みます。新しいサービスワーカーに替わったあとは、同じ操作は要りません。入れ替えが終わらず「新しいバージョンがあります」と出たときは「読み込む」を押します。

キャッシュの名前を変えるときは、`data/game.js` の `cache`、`sw.js` の `CACHE`、`index.html` の `?v=` を同じ文字列にします。

## 番号

各章の左の番号は、いまの並びから付く。章が変わるたびに 1 から振り直す。同じ章の子チャプターでは振り直さない。並べ替え、追加、削除をすると番号も変わる。子カードは親の番号に枝番を付ける。親が 3 なら、中のカードは 3-1、3-2 の順。絞り込みで隠れても、保存された並びの番号は変わらない。

## 子カード

トロフィー、アイテム入手、Tips は、直前の手順カードの中に入る。中のカードは折りたためる。チェック、タグ、トロフィーとアイテムのリンク、ID は子カード自身のまま。カード編集の「親カード」で出し入れできる。ドラッグでカードの中央に落とすと、そのカードの中に入る。親の中に、さらに親は作れない。

## アイテム

だいじなもの、消費アイテム、アクセサリー、武器、防具、マテリアは、上の「アイテム」の中の切り替えで表になる。武器はキャラクターごとに分かれ、名前を押すとその武器の強化表へ進む。上昇量は物攻、魔攻、物防、魔防の順。強化表に運やすばやさがあるときは、「その他」へ入れている。マテリアの魔法はレベルごとの行で、買値はマテリア全体、売値はレベルごと。支援・コマンド・独立は、掲載元と同じ列の表をマテリアごとに置いた。カードからのリンクは、これまでどおり `mat-im-*` などのIDを使う。召喚は「召喚獣」のタブに移した。防具とアクセサリーも一覧の列に合わせてある。数値と価格は一覧の事実で、効果の文は短くまとめた。INTERmission の装備は本編の表に混ぜず、`data/catalogs.js` の `intermission` に控えてある。画面には出さない。狭い画面では表を横に送る。

カードの「詳細」と「MAP」は、同じ行に並べ、それぞれ 44px 以上の押しやすさにしてある。

## 依頼

依頼の画面は、受注場所、条件、報酬、手順、対象の敵の数値を1件ずつ開く。文章は短くまとめ、報酬やHPなどの値は一覧の事実を使っている。地図は掲載元の画像を参照する。チャドリーレポートには、ページにあるバトルレポートの表を置いた。進行の依頼カードから「依頼の詳細」で開ける。

## 章の絞り込み

「章へ移動」は、選んだ章のカードだけを出します。初期値は「すべて表示」です。選んだ章は、本編・HARD・INTERmission ごとにブラウザへ残ります。

## アイテムの台帳

だいじなもの、消費アイテム、アクセサリー、武器、防具、マテリアは、一覧の名前を使い、説明は短くまとめています。武器はキャラクター、マテリアは種類で絞れます。INTERmission と同名のものは1件にまとめ、INTERmission だけのものは印を付けます。

アイテム入手のカードは、台帳の品と個数を持てます。カードには「名前 ×個数」と出て、押すとその台帳へ移動します。台帳側には、その品を渡すカードへのリンクが出ます。結んだカードをチェックすると「入手済み」と出ます。台帳そのもののチェックは変わりません。

## 本編の手順

本編の手順カードは、章ごとの番号順です。番号はカードの見出しに出ます。トロフィーやアイテムなどのカードは、見出しの語が合う手順の後ろに置いてあります。それらの ID は前のままです。手順カードは新しい ID（`ch01-s01` のような形）で、以前の本編カード ID は引き継ぎません。

## 地図

カードの「MAP」を押すと、地図画像をその場で表示します。「拡大」か画像を押すと画面いっぱいになり、デスクトップはホイールとドラッグ、電話はピンチとドラッグで拡大できる。「閉じる」で戻る。Chapter 18 には地図を出していません。

地図を変えるときは、カード編集をオンにしてカードの「編集」を開く。「掲載元の地図」か「保存した地図」を選ぶか、「地図の画像」に https:// の画像URLを入れる。選んだ画像は下にプレビューされる。画像ファイルを選ぶと、その場ではブラウザ内でプレビューする。400KBを超えると警告し、1.2MBを超えるファイルは入れない。「地図を外す」でMAPボタンを消す。「保存」のあと、ホバーとタップのプレビューと拡大は、その画像を使う。依頼の「編集」でも同じように地図を変えられる。

自分の画像をリポジトリに残す手順は `maps/README.md` に書いてある。掲載元の地図画像はダウンロードしない。書き出したルートは、新しい画像を `maps/` のファイルパスで参照する。同じ中身は同じファイルを使う。
